# 留白 · 浏览器新标签页

基于 React 19、TypeScript、shadcn/ui（Radix UI + Tailwind CSS）的 Manifest V3 新标签页扩展，适用于 Chrome 和 Edge。界面参考 iTab 的混合网格：网站和设置占一格，待办、随手记默认占 2×2 格，可切换为 2×3 等尺寸；没有主页侧栏。

## 本地开发

需要 Node.js 24+ 和 pnpm 11（后端使用 Node 内置 SQLite，无需另装数据库服务）。

```sh
pnpm install
pnpm dev
```

默认开发地址为 `http://127.0.0.1:9900/`。

```sh
pnpm lint
pnpm test
pnpm build
pnpm verify:extension
```

构建会生成 `dist/` 和 `blank-new-tab-1.0.0.zip`，包含全部脚本、样式与 PNG 扩展图标，不依赖远程脚本或字体。网站图标从网站自身加载，用户上传的图标保存在本机。

## 加载扩展

1. 执行 `pnpm build`。
2. 打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`。
3. 开启开发者模式，点击「加载已解压的扩展程序」，选择本项目的 `dist` 文件夹。
4. 打开新标签页；如果浏览器询问是否保留新标签页变更，选择保留。

个人使用直接加载本地扩展即可，无需发布商店或支付商店注册费。`public/manifest.json` 中的 `key` 是固定公钥，同一份扩展在不同目录、电脑及 Chrome/Edge 中加载时，ID 均为 `nplbljhenhbjjccehgckeanlbiknanoe`。保留这个公钥即可保持 ID；它不是 GitHub 密钥。

从未固定 ID 的旧版本切换时，先导出本地备份；新 ID 对应独立的本地存储，加载后需导入备份并重新登录。

ZIP 是分发包；本地加载前先解压，或直接使用 `dist`。修改代码后重新构建，在扩展管理页点击刷新，再重新打开新标签页。扩展使用 `identity` 权限打开 GitHub OAuth 授权窗口，不读取浏览器账号资料、浏览历史或标签页。首次读取网站名称与图标、连接云端备份服务器时，会请求对应站点的可选访问权限。

## 后端与云端备份

后端使用 **TypeScript + Node.js 24 + Fastify + SQLite**，代码在 `server/`。前后端复用 Zod 工作区与备份校验规则。**云端仅允许 GitHub 登录，没有本地注册、账号密码登录或密码存储。** 支持多份备份的保存、列表、恢复、删除；每个 GitHub 账号只能访问自己的备份。

插件固定连接 `https://tabsapi.lianhb.site`，地址定义在 `src/lib/cloud-server.ts`；页面没有服务器地址输入或切换入口。登录、自动上传和手动恢复共用该地址，其他服务器留下的会话和未完成登录请求需要重新登录。后端的 `HOST`、`PORT` 仅控制服务器监听地址，不参与前端地址配置。

本地调试后端时，在项目根目录执行：

```sh
pnpm install
pnpm server:dev
```

打开已构建的扩展，进入「设置 → 数据备份 → 云端备份」，点击「使用 GitHub 登录」，在 GitHub 官方页面授权。扩展会打开独立的浏览器授权窗口。**登录后的修改会自动上传，其他设备需手动拉取。** 选择「拉取并恢复」会先展示内容数量，再确认替换当前桌面；恢复后可通过提示撤销。每个账号默认保留最近 20 份备份；同一设备 10 分钟内的自动上传更新同一份，手动点击「立即上传」单独新增一份。不同设备的自动备份分别合并。删除云端备份需要确认且无法撤销，不会删除本地工作区。

自动上传在整个桌面页面运行，不依赖设置面板是否打开。内容先保存到 IndexedDB，再上传到当前服务器和 GitHub 账号；连续输入、拖动和设置调整会合并，在最后一次修改保存后约 1.2 秒上传最新版本。上传期间的新修改会继续排队。桌面底部和云端备份面板会显示等待、上传中、最近上传时间或具体错误；失败保留待上传内容，可点击「重试上传」，再次修改也会上传最新版本。退出登录停止上传，待上传记录按服务器和 GitHub 账号隔离；页面关闭后暂停，下次在同一浏览器登录同一账号打开页面时继续处理。

单纯打开页面或登录不会把当前旧内容上传成新备份，也不会下载远端工作区。没有修改时可点击「立即上传」保存当前桌面。点击「刷新」只更新备份列表；只有手动选择「拉取并恢复」并确认后，才会替换本机工作区。本机确认导入或恢复后的内容也属于本机修改，会按相同规则上传。修改后立即关闭页面时，未完成上传的内容保存在本机待上传记录中；需要在另一台设备取到这次修改时，先确认原设备已经显示上传成功。

待上传记录和本机工作区在同一 IndexedDB 事务中保存；不同标签页使用浏览器锁协调同一账号的上传。手动快照单独排队，后续自动编辑只合并自动上传队列。设备标识是保存在当前浏览器或扩展 IndexedDB 中的随机 UUID，不采集硬件信息。升级前已排队的上传按独立快照处理。

自动备份的合并窗口从该份备份首次创建时起计算，窗口内继续上传不会延长窗口。列表按最后更新时间排序。保存新内容后，服务器在同一事务内清理超出数量上限的最旧备份；写入或清理失败会整体回滚。启动服务时也会按当前上限清理已有超额历史。每条上传请求携带持久化的幂等标识；保留中的备份可识别旧请求重试，重试不会把已合并的新内容改回旧版本。同一标识提交不同内容返回 409；请求记录随对应备份的删除一起清理。

### 任务结果推送

在「设置 → 推送」生成专用令牌，复制 MCP 配置到 Codex 后，定时任务可调用 `send_result` 投递完整结果。新标签页右上角显示常驻堆叠通知，最多两行；关闭通知会标记已读，点击被省略的内容会打开全文弹窗并标记已读。已读状态跨设备同步，网络失败时保留本机待同步记录。

推送令牌仅允许发送消息。接入方式、工具参数、接口和部署步骤见 [任务结果推送](docs/push-messages.md)。

### 创建 GitHub OAuth App

1. 打开 [GitHub Developer settings → OAuth Apps](https://github.com/settings/developers)，点击 **New OAuth App**。个人 GitHub 账号即可创建。
2. 为当前部署填写以下内容：
   - **Application name**：`留白新标签页`（可自定义）。
   - **Homepage URL**：填写项目主页地址。
   - **Authorization callback URL**：`https://tabsapi.lianhb.site/api/v1/auth/github/callback`。
3. 注册应用，复制 **Client ID**，点击 **Generate a new client secret** 生成密钥。
4. 在服务器配置中填写 `GITHUB_CLIENT_ID` 和 `GITHUB_CLIENT_SECRET`，将 `GITHUB_CALLBACK_URL` 设为上面的 HTTPS 回调地址。systemd 部署使用 `/etc/blank-backup.env`；本地后端使用 `.env.server`。密钥只放后端配置，不发聊天、不提交 Git、不放前端环境变量或扩展包。
5. 重新启动后端，打开扩展进行 GitHub 登录。不需要启用 Device Flow，也不需要申请仓库或邮件权限。

本地扩展的固定返回地址为 `https://nplbljhenhbjjccehgckeanlbiknanoe.chromiumapp.org/github`，已加入 `.env.server.example` 的 `GITHUB_RETURN_URLS`。使用已有环境文件时，将此地址加入该配置，多个地址以英文逗号分隔，然后重启后端。**GitHub 后台的 callback URL 填写后端 `/api/v1/auth/github/callback`。** 后端只接受已配置的完整返回地址。

如需使用网页开发模式登录，将网页的完整返回地址加入后端 `GITHUB_RETURN_URLS`；网页和扩展均使用源码中固定的后端地址。

如需自定义配置，将 `.env.server.example` 复制为 `.env.server`；开发和生产启动命令都会读取它。环境变量优先于文件配置，无效配置会使启动失败并打印原因。

| 配置                        | 默认值                                              | 用途                                                 |
| --------------------------- | --------------------------------------------------- | ---------------------------------------------------- |
| `HOST`                      | `127.0.0.1`                                         | HTTP 监听地址                                        |
| `PORT`                      | `3001`                                              | HTTP 端口                                            |
| `DATABASE_PATH`             | `server/data/blank.sqlite`                          | 相对项目根目录或绝对 SQLite 文件路径                 |
| `SESSION_DAYS`              | `30`                                                | 登录会话有效天数，必须为正数                         |
| `BACKUP_LIMIT`              | `20`                                                | 每个账号保留的备份总数，手动和自动合计，必须为正整数 |
| `AUTO_BACKUP_MERGE_MINUTES` | `10`                                                | 同一设备自动备份的合并窗口分钟数，设为 0 时每次新增  |
| `GITHUB_CLIENT_ID`          | 空                                                  | GitHub OAuth App 的 Client ID                        |
| `GITHUB_CLIENT_SECRET`      | 空                                                  | GitHub OAuth App 的密钥，仅在后端使用                |
| `GITHUB_CALLBACK_URL`       | `http://127.0.0.1:3001/api/v1/auth/github/callback` | GitHub 后台登记的后端回调地址                        |
| `GITHUB_RETURN_URLS`        | `http://127.0.0.1:9900/`                            | 允许返回的网页/扩展完整 URL，以英文逗号分隔          |

Client ID 和 Secret 均未填写时，服务启动会明确警告，GitHub 登录接口返回 503，界面显示缺少配置；不会生成模拟登录会话。两者只填写一项或配置格式不正确时，启动失败并显示错误。

生产构建和启动：

```sh
pnpm server:build
pnpm verify:server
pnpm server:start
```

构建将后端业务代码合并为 `server-dist/index.mjs`，Fastify、Zod 等第三方依赖保持外部引用。生成的 `browser-tabs-server.tar.gz` 包含后端产物、`package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、部署模板和文档。服务器安装 Node.js 24 和 pnpm 后，在解压目录执行 `pnpm install --prod --frozen-lockfile` 安装生产依赖，再启动后端；无需上传 TypeScript 源码或本机 `node_modules`。单独运行时可执行 `node --env-file=.env.server server-dist/index.mjs`；systemd 部署使用 `/etc/blank-backup.env`。`pnpm verify:server` 会在项目外的独立目录解压部署包、安装生产依赖，检查 HTTP、CORS、参数校验和重启后的 SQLite 数据保留。

部署时持久化 `DATABASE_PATH` 所在目录，通过 `https://tabsapi.lianhb.site` 的 HTTPS 反向代理将 `/api/v1/` 转发到后端。SQLite 使用 WAL，维护备份时应停服后复制整个数据库目录，或使用 SQLite 的在线备份工具，不要在运行中仅复制主数据库文件。

Debian 12 的安装、上传、systemd 常驻运行、Nginx HTTPS 和数据维护步骤见 [部署文档](docs/deploy-debian12.md)，配置模板位于 `deploy/`。

GitHub Actions 的一次性配置见 [自动部署文档](docs/github-actions.md)。推送到 `main` 后，同一个任务依次完成后端检查、打包、SSH 上传、服务器安装依赖和重启；启动失败时尝试恢复旧版。可在本机执行 `pnpm server:check` 检查后端。

日常部署入口为 `.github/workflows/deploy.yml` 和 `deploy/deploy.sh`；服务器初始化命令放在部署文档中，部署及后端包验证脚本位于 `tests/`。

接口前缀为 `/api/v1`，除健康检查和 GitHub OAuth 握手外使用 `Authorization: Bearer <token>`，不使用 Cookie。接口响应不允许缓存，错误返回非 2xx 状态和 `{ "error": "原因" }`。

| 方法   | 路径                    | 功能                                                                                                     |
| ------ | ----------------------- | -------------------------------------------------------------------------------------------------------- |
| GET    | `/health`               | 服务健康检查                                                                                             |
| POST   | `/auth/github/start`    | `{ "returnUrl": "完整返回地址", "codeChallenge": "S256挑战值" }`，创建授权请求并返回 GitHub URL 和 state |
| GET    | `/auth/github/callback` | GitHub 回调，验证 state 后向已登记的页面转交一次性授权结果                                               |
| POST   | `/auth/github/complete` | `{ "state": "...", "code": "...", "codeVerifier": "..." }`，后端验证 GitHub 身份并签发本地会话           |
| GET    | `/auth/me`              | 当前账号                                                                                                 |
| POST   | `/auth/logout`          | 撤销当前会话，返回 204                                                                                   |
| GET    | `/backups`              | 当前账号的备份摘要，最新的排在前面                                                                       |
| POST   | `/backups`              | 上传与本地 JSON 导出相同的 `blank-backup` 对象，返回 201 和摘要                                          |
| GET    | `/backups/:id`          | 下载完整备份                                                                                             |
| DELETE | `/backups/:id`          | 删除当前账号的一份备份，返回 204                                                                         |

上传可附带 `Idempotency-Key`（UUID）、`X-Backup-Mode`（`automatic` 或 `manual`）、`X-Backup-Device`（本机随机 UUID）。自动上传必须提供设备标识；未指定模式的请求按手动快照保存。备份摘要的 `createdAt` 是该份快照的创建时间，`updatedAt` 是最后更新内容的时间。

登录使用 GitHub 官方 OAuth Web Flow，客户端生成 PKCE S256 证明，服务器生成一次性随机 state。授权请求有效期为 10 分钟，完成时原子消费；错误、取消或失败均明确提示，需由用户重新发起。网页临时证明仅放在当前标签页的 sessionStorage，返回时清理地址中的授权参数；扩展临时证明仅留在授权调用内存中。Client Secret、GitHub access token 都不交给前端；GitHub token 仅用于本次 `/user` 身份读取，不保存到数据库。登录不请求仓库、私人资料或邮件权限。

账号归属使用不可变的 GitHub 数字 ID，GitHub 登录名变化只更新显示名称，不影响已有备份；不同 ID 即使同名也不会合并。随机本地会话令牌仅以 SHA-256 哈希存入数据库，退出立即撤销。浏览器保存服务器地址和本地会话令牌，登录信息不会放进工作区或备份文件。因服务器离线而无法退出时，可在错误提示处主动清除本机登录信息；这不会撤销服务端会话，后者到期后失效。

从旧账号密码版本升级时，数据库会移除旧账号和密码字段并撤销旧会话，不会按用户名猜测并绑定 GitHub 账号。如果旧账号有云端备份，迁移会先将完整 JSON 和账号索引导出到数据库同目录的 `legacy-backups-<时间戳>/` 并打印路径，导出失败则回滚迁移。使用 GitHub 登录后，可在设置中导入这些文件并重新上传。本地工作区不受影响；若浏览器仍保存旧登录信息，按界面提示清除后使用 GitHub 登录。当前 SQLite 版本为 4，从 GitHub 登录版升级会保留已有身份、会话、备份和幂等请求记录。已有备份作为独立快照保留。

云端采用自动上传、手动拉取的快照备份方式，其他设备通过手动恢复更新工作区。GitHub 首次授权成功后自动建立身份记录，项目不处理用户密码。备份数量由 `BACKUP_LIMIT` 控制；对公网开放时由部署方配置 HTTPS、入口限流、请求体大小及磁盘监控。备份包含原始图标和壁纸，代理上传大小设置需要容纳这些图片。数据库中的备份内容未做端到端加密，服务器管理者可读取，因此应连接自己信任的服务器。

## 使用

桌面、组件及弹窗的普通文本禁止鼠标选中；输入框和正文编辑区保留正常的文字选择与编辑。

- **待办**：在小组件底部直接输入，Enter 添加；文字可就地修改，复选框完成任务。标题或展开按钮打开完整清单。删除与清理已完成项均提供撤销。
- **随手记**：点击标题、备忘条目或新建按钮打开编辑器，支持标题、多段长文本、自动保存、删除和撤销。
- **网站与图标**：在桌面空白处右键选择「添加图标」创建入口，输入网址后自动读取真实网站名称与站点图标，默认使用站点图标。图片占满图标区域并等比显示，外围负责圆角裁切，没有额外的小 favicon 底板。图标来源可选网站图片、文字、上传图片和原有系统预设；编辑时可保留当前图片。文字支持中文和英文，单行居中，较长内容自动缩小，图标文字与网站名称独立。未取得网站图片时可以使用文字图标；读取与图片加载失败均明确显示。背景色支持预设、自定义色和透明；静态大图会按显示尺寸缩小，支持浏览器可解码的 SVG、PNG、JPG、WebP、GIF 等图片。读取请求直达用户输入的站点，不经过第三方解析服务，不携带账号 Cookie。
- **分组**：在桌面空白处右键选择「新建分组」，填写分组名称即可创建。也可将一个网站拖到另一个网站中央，停留约 450 毫秒后松手，快速建立分组。分组弹窗标题右侧的编辑按钮可修改名称。网站可在桌面、大布局分组和分组弹窗之间拖入、拖出，也可通过右键菜单移动。解散分组会保留其中的网站。
- **系统预设图标**：提供 200 个精选 Lucide 图标，覆盖导航、工作、开发、学习、交流、影音、生活、健康和工具九类，支持中文、英文与关键词搜索。每页展示 48 个图标，可选择预设色或自定义颜色。图标随扩展静态打包，打开选择器和翻页时即可显示，无需联网；旧存档中的 GitHub、Figma、Notion 图标继续兼容。
- **文字图标颜色**：新增或编辑网站时，选择「文字图标」后可分别设置「文本颜色」和「图标背景色」，预览实时更新。
- **分组预览与点击**：1×1 显示四个缩略图；2×1、1×2 分别横排、竖排三个；2×2 显示前三个大图标，并将后续最多四个缩略图组合在右下角；4×2 最多显示八个大图标。内部图标始终保持正方形，窗口、间距和尺寸变化时按实际容器重新排布。2×2 和 4×2 中显示的网站均可直接打开、拖动排序或移出，遵循「在新标签页打开网站」设置；其他尺寸的缩略图、空白区域或分组名称打开完整分组。拖动空白区域或分组名称可移动整个分组。预览未显示的网站仍保留在分组中。
- **移动与尺寸**：网站和小组件共用可定位网格，空白格也能放置，支持移动到最右侧。桌面网站和分组右键可选择 1×1、2×1、1×2、2×2、4×2 五档布局；分组默认为 2×2，并显示内部网站缩略图。小组件从头部拖动，底部没有额外文字。待办和随手记右键可选择 2×2、2×3、3×2、3×3、4×2、4×3 六档尺寸，调整后自动安置冲突的图标。网站和分组通过共用浮层跨区域拖动，松手后直接落位；小组件拖动时移动原卡片。位置和尺寸都会保存。键盘聚焦后按 Space 抓起，方向键移动，Space 放下，Escape 取消。分组内的网站按统一尺寸连续排列，拖动只调整顺序，移出或删除后自动补位；「添加网站」固定在最后一项，不参与拖动。网站和分组的操作菜单通过右键或键盘菜单键打开。
- **自适应槽位与分页**：桌面和分组共用有边界的槽位网格，按可用宽高确定每页容量，放不下时分页，不通过拖动撑出滚动条。只有多页时才显示分页。需要跨页时，将鼠标停在分页箭头上，或使用 PageUp / PageDown。窗口缩小、放大时分别读取对应网格的布局，窄窗口中的移动、改名不会覆盖已有宽屏坐标。图标超过当前页容纳尺寸时会按可用槽位收缩显示，回到大窗口恢复所选尺寸。
- **整理**：「设置 → 常规 → 整理桌面图标」按当前窗口槽位重新排列，并提供撤销。该操作只修改当前网格尺寸的布局，适用于旧版本已经丢失原排列的情况。
- **设置**：在桌面空白处右键选择「设置」打开右侧面板；同一菜单提供「添加图标」和「新建分组」。常规偏好、主题与壁纸、备份都在这里。「主题与壁纸 → 外观模式」可选择纯白、纯黑或跟随系统；选择会保存，卡片和弹窗统一使用中性灰阶。默认「纯净」背景随模式切换为 #FFFFFF 或 #000000。壁纸提供前端定义的纯色、渐变和用户上传图片，可通过「壁纸模糊」滑动条调整 0–30 px 模糊，设置自动保存。
- **图标外观**：「设置 → 图标」调整默认圆角或圆形、图标大小、圆角半径、不透明度、横纵间距、名称显示、名称字号与颜色，以及图标区域最大宽度。名称默认跟随桌面文字颜色，适应纯黑、纯白和图片壁纸；自定义后使用所选颜色。默认图标为 60px、圆角 18px、间距 30px、名称 12px。分组内图标和缩略图也使用这些外观设置。
- **弹窗与抽屉**：设置抽屉不渲染遮罩、不模糊背景，也没有向桌面扩散的阴影，可以直接预览桌面。普通弹窗使用 Radix Dialog，只做短暂淡入淡出，不缩放或位移。分组弹窗带遮罩并阻止操作桌面。图标拖到弹窗外持续 500ms 后关闭弹窗，移回则取消计时；在外部放下也会按原计时关闭。弹窗关闭后仍可继续拖动并放到桌面或其他分组。分组首次绘制前完成槽位测量，关闭动画期间保留内容。高度按完整图标行收紧，超过屏幕可用高度后分页，图标区域上下各留 16px。名称使用弹窗主题色，独立于桌面自定义名称颜色。分组预览容器采用随黑白主题变化的中性色背景。
- **桌面半透明表面**：搜索框、小组件和分组使用半透明底色，不对壁纸实时做背景模糊，避免相邻图标悬浮缩放时出现白块或绘制残影。
- **搜索**：支持必应、Google、百度；点击搜索框左侧切换。页面非编辑状态下按 `/` 聚焦搜索。搜索是用户主动提交后才打开第三方搜索服务。

## 数据

工作区、上传图片和待上传记录保存在当前浏览器、当前扩展的 IndexedDB 中，本地使用无需账号或服务器。GitHub 登录后，修改会自动上传到用户填写的服务器；其他设备的工作区只能通过手动拉取并确认恢复。保存失败会明确提示并提供重试，不会用默认数据覆盖读取失败的存档。清除扩展数据、卸载扩展或清理浏览器站点数据可能移除本地内容及尚未上传的修改，建议在设置中导出文件，并留意上传状态。

JSON 备份包含待办、备忘、图标来源、文字图标及文本颜色、上传图标图片、分组、不同网格尺寸的桌面与分组布局、网站与组件尺寸、图标外观、其他偏好和壁纸图片。导入先校验结构与网站协议，再展示替换确认；错误文件不会替换当前工作区。旧存档会补齐新增图标设置并保留原有网站、预设图标和内容。开发站点与正式扩展属于不同来源，数据不互通，可通过备份迁移。

「设置 → 数据备份 → 导入备份」也支持 Infinity v2 的 `.infinity` JSON 文件。多页网站按原顺序合并，保留分组、图片图标、文字图标与背景色；随手记的 HTML 转成文本，保留文字、换行与修改时间。内置应用和非网页链接会列在导入预览中；壁纸、天气、搜索和界面设置不迁移，保留当前留白设置。当前样例的待办为空；含非空 Infinity 待办的文件会明确报错并取消导入，待确认其实际结构后再支持。确认替换后可通过提示撤销。

### 图片与加载

上传的静态大图标会按比例缩小至 256×256 以内；静态大壁纸按屏幕像素尺寸缩小。缩小后的图片使用 WebP，GIF、动画 PNG/WebP、AVIF 和 SVG 保留原文件。壁纸亮度分析结果保存在本机，重新打开页面时复用。

设置、编辑器、备份面板和图片处理模块使用静态导入。连续编辑合并保存，持续输入达到 1 秒时触发写入；有未保存内容时离开页面会触发保存并显示浏览器确认。

新版本读到全量图标库版本保存的 `lucide:` ID 时，会转换为对应的精选图标 ID；未保留的图标回退为通用地球图标。新增精选图标和文本颜色仍需同步部署服务端的共享校验规则，数据库结构无需迁移。

后续新增小组件时，在 `widgets/` 内独立实现组件，并在 `App.tsx` 的 `widgets` 列表注册唯一 `id`、名称、`sizeKey` 和内容；在尺寸模型中声明预设后，网格会处理占位、拖拽和位置持久化。业务数据与操作保存在 `workspace.ts` 和相应组件内，不放进网格基础层。

动画使用 Motion 的页面与弹窗过渡，以及 CSS 的悬停和面板进出动画。桌面拖动只让其他图标让位，小组件内部不播放布局动画。时钟使用本机 Arial / Helvetica 无衬线数字，不加载远程字体；日期、辅助文字和输入框占位文字统一使用较深的主题文字色。系统「减少动态效果」偏好和设置中的「减少动画」都会生效。

开发与预览中的 `/api/site-metadata` 由 Vite 中间件提供；打包后的扩展通过后台 Service Worker 读取网页。两者调用相同的真实抓取逻辑，不使用模拟响应或第三方代理。

浏览器能打开网站不代表 Node 开发服务也能连接该网站：两者的网络权限、代理、证书信任与 Cookie 环境可能不同。读取失败时会显示已知的底层错误原因，例如 `EACCES` 表示进程连接被系统或运行环境拒绝，`ENOTFOUND` 表示域名解析失败；此类错误发生在解析网页图标之前。

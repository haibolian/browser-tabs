# 任务结果推送

## 接入

1. 在插件中登录，打开「设置 → 推送」。
2. 输入令牌名称，点击「生成令牌」。完整令牌仅显示一次。
3. 点击「复制 MCP 配置」，将配置添加到 Codex 的 MCP 配置中并重新连接。也可以分别复制服务地址和令牌，使用 Bearer 鉴权。
4. 在定时任务中加入：任务完成后，调用 `send_result` 发送标题和完整正文。为本次执行提供稳定的 `requestId`，失败重试时保持该值及内容不变。

MCP 地址固定为 `https://tabsapi.lianhb.site/api/v1/mcp`，使用无状态 Streamable HTTP。示例配置中的令牌需替换为自己生成的值：

```toml
[mcp_servers.blank]
url = "https://tabsapi.lianhb.site/api/v1/mcp"
http_headers = { Authorization = "Bearer 替换为推送令牌" }
```

`send_result` 参数：

```json
{
  "title": "每日资讯",
  "content": "任务生成的完整正文",
  "requestId": "daily-news-2026-11-18T09:00:00+08:00"
}
```

`title` 可省略，最长 200 字符；`content` 必填，最长 100,000 字符；`requestId` 可省略，提供时最长 128 字符。同一账号以相同标识重试会返回原消息；内容不同则报错，已经读过的消息不会重新变成未读。

## 展示与已读

打开新标签页时读取未读消息；页面可见期间每 30 秒刷新一次，重新聚焦、恢复网络时也会刷新。右上角使用 Sonner 堆叠通知，默认最多显示两行，超过部分省略。推送通知持续保留，右侧关闭按钮将消息标记为已读；内容被截断时，点击正文打开完整信息 dialog，并关闭对应通知、标记已读。

刷新和退出页面不会自动标记已读。已读状态保存到服务器，在其他设备刷新后同步；网络失败时，本机保存待同步的已读标识，后续刷新重试，不会重新弹出已关闭的消息。同一浏览器多个标签页通过本地事件和 storage 事件同步已读状态。

## 接口

| 方法与地址                        | 鉴权         | 功能                                         |
| --------------------------------- | ------------ | -------------------------------------------- |
| `POST /api/v1/mcp`                | 推送令牌     | MCP 握手、发现和调用 `send_result`           |
| `POST /api/v1/push/messages`      | 推送令牌     | 直接通过 HTTP 投递，参数与工具一致           |
| `GET /api/v1/push/messages`       | 插件登录会话 | 读取当前账号未读消息                         |
| `POST /api/v1/push/messages/read` | 插件登录会话 | 批量标记已读，正文为 `{"ids":["消息 UUID"]}` |
| `GET /api/v1/push/tokens`         | 插件登录会话 | 列出脱敏的令牌信息                           |
| `POST /api/v1/push/tokens`        | 插件登录会话 | 创建令牌，正文为 `{"name":"Codex"}`          |
| `DELETE /api/v1/push/tokens/:id`  | 插件登录会话 | 撤销指定令牌                                 |

推送令牌只允许投递结果，不能读取消息、管理令牌或操作备份。服务器仅保存令牌的 SHA-256 哈希，完整值仅在生成时返回；令牌持续有效，用户可在设置中撤销。每个账号最多 10 个令牌，每分钟最多接收 60 条新消息，最多积压 200 条未读消息。已读记录在后续投递时清理超过 30 天的部分。

## 部署

前后端都需要更新。构建后端部署包并按现有流程安装生产依赖、重启服务；插件重新构建、更新扩展并打开新标签页。MCP 和推送接口都位于现有 Nginx 模板已转发的 `/api/v1/` 下。

推送数据保存在现有 SQLite 数据库的独立表中，复用同一账号。新增表保持原数据库版本号，以便上一版后端在程序回滚后仍可启动。推送正文与备份一样存储在自己的服务器上，服务器管理者可读取。
